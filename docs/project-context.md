# הקשר הפרויקט — מסמך מלא ומעודכן

מסמך הקשר מרכזי לפרויקט, לשמירה בתיקיית `docs/`. נועד שכל מי שעובד על הפרויקט — Claude Code, וכל צ'אט תכנון — יראה את התמונה המלאה: המטרה, הארכיטקטורה, מבנה האתר, דרישות הפרופסור, הכלים, ההחלטות, והסטטוס. עודכן: 20.10.2026.

## מי ומה
נועה, עובדת חדשה במעבדה של פרופ' יורם לוזון. ללא ניסיון קודם בתכנות. התפקיד: לכוון ולבדוק; Claude Code כותב את הקוד בפועל, בצעדים קטנים שמוצגים לאישור.

## המטרה
פלטפורמה אחת חכמה שמאחדת את חמשת כלי המיקרוביום של אושרית שטוסל (MIPMLP, iMic/gMic, miMic, GIMIC, LOCATE), ויודעת לבחור באיזה כלי להשתמש לפי השאלה והנתונים — ברמה מקצועית גבוהה מאוד.

## הארכיטקטורה (הרעיון)
ייצוג משותף אחד: כל הכלים מתחילים מ-MIPMLP ← עץ טקסונומי של log-frequencies, שמחושב **פעם אחת**. מעליו:
- **פרופיילינג אוטומטי** של הנתונים (תוויות? מטבוליטים? סדרת-זמן?).
- **נתב חכם** שבוחר כלי ומנמק.
- **ארבעה מנועים** שמתחברים זה לזה: iMic/gMic (ניבוי), miMic (מבחן סטטיסטי), GIMIC (מרחק/קיבוץ), LOCATE (מיקרוביום+מטבולום).
- **פלט מאוחד** + הסבר (XAI) + דוח לשחזור, על תשתית אחת (חבילת Python + Flask + Python 3.13).

## מבנה האתר (מהמצגת לפרופסור)
- **חמישה עמודים:** Home · New analysis · Example · Methods · Docs & API · About. האתר באנגלית.
- **ניתוח = אשף של 4 שלבים:** Upload (קובץ חובה אחד + בדיקה מיידית) ← Data check (פרופיל אוטומטי) ← Plan (המלצה עם נימוק; המשתמש רק מאשר) ← Results (תקציר, לשונית לכל כלי, דוח שחזור).
- **דף הבית:** כניסה לפי שאלה ("אילו חיידקים שונים בין קבוצות?"), לא לפי שם כלי.
- **עיקרון מנחה:** לבקש מהמשתמש כמה שפחות; האתר שכבה דקה מעל חבילת Python אחת.

## דרישות הפרופסור (20.10) — אושרו
1. **ריצות כבדות לא תלויות בדפדפן:** ריצה ברקע עם ID ייחודי + קישור-תוצאה; אימייל אופציונלי להתראה בסיום ושליחת/הורדת תוצאות. לא נדרש ל-MIPMLP הקל; חובה לפני iMic/LOCATE. (שליחת מייל דורשת SMTP — לסדר מול המעבדה.)
2. **שגיאות העלאה חדות:** לכל קלט שגוי (פורמט/עמודות) — לעצור עם הודעה ברורה: מה השגיאה, איך לתקן, והפורמט/דוגמה הצפויים.
3. **אופציה "רק עיבוד מקדים" (MIPMLP בלבד)** — למי שרוצה רק את הטבלה הנקייה.
4. **תוצאות גם כ-Figures וגם כ-CSV** להורדה/עריכה; כל גרף מגיע עם ה-CSV שמאחוריו, ואינטראקטיבי במידת האפשר.
5+6. **חבילה-תחילה, אתר דק:** כל הלוגיקה בחבילת Python אחת, מותקנת/ניתנת ל-import וציטוט; האתר שכבה דקה שרק מייבאת אותה, בלי לוגיקה בשכבת ה-web. החבילה היא המוצר הראשי (שומר נתונים קליניים אצל החוקר). תואם לארכיטקטורה שכבר נבנתה.

## החלטות מפתח
- **סטאק:** Python 3.13 + Flask; GitHub פרטי; pandas מוצמד ל-2.3 (pandas 3 שובר את MIPMLP).
- **עיבוד:** ריצה קנונית אחת + שינויים מוצהרים לכל כלי + caching; הגדרות המאמר (לא ברירות המחדל).
- **גרסה 1 = MIPMLP** קצה-לקצה, ואז miMic.
- **נרמול:** log של הספירות (לא relative) — המאמר הראה ש-log עדיף; ברירת מחדל עם מתג קל ל-relative. לאמת עם אושרית.
- **שימוש מול בנייה:** חבילות ה-pip הן הקוד של המחברים (מריצים, לא כותבים מחדש). גרסת מעבדה פנימית = שדרוג, לא תנאי לנכונות (חוץ מ-LOCATE).
- **דאטהסטים:** עדיין אין אמיתי — בינתיים קובצי דוגמה של המחברים; לבקש מאושרית.

## חוזה הנתונים המשותף (Data contract)
כל הכלים בפלטפורמה עומדים על **אותם קלטים ואותו ייצוג** — לעולם לא יקרה שכלי אחד מצפה לעמודות מסוימות וכלי אחר לעמודות אחרות. החוזה מוגדר **במקום אחד בקוד**: `src/microplatform/core/contract.py`.
- **מוסכמות הקלט:** העמודה הראשונה בכל טבלה היא `ID` (מזהה דגימה, נקרא כטקסט); השורה האחרונה בטבלת הספירות היא `taxonomy`; עמודת התוויות נקראת `Tag` (עמודה יחידה בשם אחר מתקבלת ומשונה ל-`Tag`); דרגות הטקסונומיה מופרדות ב-`;`.
- **סוגי קלט:** ספירות (counts), תוויות (labels), מטבוליטים (metabolites), נקודות זמן (timepoints).
- **הייצוג הקנוני (`Dataset`):** הפלט של MIPMLP — שורה לכל דגימה, עמודה לכל feature, מספרים בלבד, בלי ערכים חסרים; התוויות מיושרות לאותן דגימות. **כל מנוע מקבל רק את זה** — אף פעם לא את הקובץ הגולמי.
- **שינויים מותרים לכל כלי:** רק רמת הטקסונומיה ו-z-scoring. הנרמול (log), הקיבוץ (sub-PCA) וסף החיידקים הנדירים זהים לכל הכלים.
- **אכיפה:** מבחן אוטומטי (`tests/test_contract.py`) נכשל אם מנוע כלשהו סוטה מהחוזה — דורש קלטים שונים מהמשימה שלו, משנה הגדרה אסורה, מקבל משהו שאינו ה-`Dataset`, או אם שם של מוסכמה מוקלד מחוץ לקובץ החוזה. הודגם שהמבחן תופס מנוע "שבור".

## קלטים לכל משימה (ההעלאה מותאמת למשימה)
| משימה | כלי | נדרש |
|-------|-----|------|
| רק עיבוד מקדים | MIPMLP | ספירות |
| אילו חיידקים שונים בין קבוצות | miMic | ספירות + תוויות |
| ניבוי התוצאה | iMic (בהמשך 3D-iMic: + נקודות זמן) | ספירות + תוויות |
| איך הדגימות מתקבצות | GIMIC | ספירות |
| קשר בין חיידקים למטבוליטים | LOCATE | ספירות + מטבוליטים |

ההגדרה נמצאת במקום אחד (`router/goals.py`), וכל מנוע חייב להתאים לה (נבדק אוטומטית). חוויית המשתמש: מעלים את מה שיש; המערכת מזהה כל קובץ; בשלב ה-Plan כל משימה שחסר לה קלט אומרת בדיוק מה חסר ("Needs a labels file") ומאפשרת להוסיף אותו במקום, בלי להתחיל מחדש. לעולם לא מבקשים קובץ שהמשימה לא צריכה. זיהוי קובצי מטבוליטים ונקודות זמן ייבנה יחד עם LOCATE ו-3D-iMic.

## החבילה (המוצר הראשי)
החבילה נמצאת ב-`src/microplatform/` וניתנת ל-import כ-`microplatform`. היא כוללת: `core/` (החוזה, הפרופיילר, זיהוי קבצים, עיבוד מקדים, הודעות שגיאה), `engines/` (מתאם לכל כלי), `router/` (המשימות, ובהמשך כללי הנתב), `reports/` (גרפים, ZIP תוצאות), `runs.py` (שמירת ריצות), `workflows.py` (תהליכים מקצה לקצה) ו-`examples/` (דוגמה ותבניות). האתר (`web/`) הוא שכבה דקה מעליה. כבר היום ניתנת להתקנה מקומית (`pip install -e .`). התוכנית: (1) API ציבורי קטן ומתועד, עם מספרי גרסה ויומן שינויים; (2) Flask כתוסף אופציונלי (`pip install microplatform[web]`), כך שחוקרים יוכלו לנתח נתונים קליניים אצלם בלי האתר; (3) פרסום ב-PyPI (לוודא שהשם פנוי); (4) ציטוט: קובץ `CITATION.cff` ו-DOI ב-Zenodo לכל גרסה, עם רשימת מחברים שהמעבדה תקבע.

- **הבא:** מדידת זמני ריצה על שרת המעבדה אחרי ההתקנה (ואז כוונון ה-4 שעות); החלטות המעבדה מרשימת ההחלטות.
- 🔌 **תלות פתוחה — שרת מייל (SMTP) מהמעבדה:** התראת המייל בסיום ריצה היא רכיב אופציונלי שיופעל רק כשנקבל מהמעבדה את פרטי השרת (כתובת שרת, פורט, משתמש וסיסמה, כתובת שולח). עד אז הריצה ברקע וקישור התוצאה עובדים במלואם, ושדה המייל פשוט לא מוצג.
